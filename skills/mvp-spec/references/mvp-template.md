# MVP 요건 템플릿

`§0-3` 조건(진행 차단 항목 미충족)에 해당할 때 사용자에게 제공하는 골격이다. 8개 항목만 담고 그 외는 넣지
않는다 — PRD 전체가 아니라 **게이트 통과에 필요한 최소 요건**이다.

사용자가 직접 채우거나, PM 계열 스킬·PRD 템플릿으로 작성한 내용을 이 구조에 옮긴다. 사용자가
**질의 보완 모드**(`references/fill-mode.md`)를 고르면 질문의 답을 이 구조에 채워 초안을 만든다.

---

## 제공 방식

파일로 만들어 제공한다. 안내 문구에 항목 이름만 나열하지 않는다 — 채울 자리가 있는 편이 훨씬
빨리 작성된다.

파일명은 `Master.md` 또는 `{서비스명}_Master.md`를 권한다. 게이트가 "여러 화면에 걸리는 규칙"을
찾는 문서와 같은 위치이므로 하나로 두는 편이 관리가 쉽다.

## 템플릿 본문

````markdown

tags: [draft]
work_type: new | renewal | enhancement    # 필수 — 게이트 분기 트리거
updated: YYYY-MM-DD

# {서비스명} — Master

## 0. 작업 유형

**이 항목이 점검 범위를 결정한다.** 유형에 따라 필수 항목이 달라지므로 먼저 적는다.

| 유형 | 언제 | 점검 대상 |
|---|---|---|
| `new` 신규 | 서비스 자체를 새로 정의 | 1~7 전부 |
| `renewal` 리뉴얼 | 기존 서비스의 구조를 다시 짬 | 1~7 전부 |
| `enhancement` 고도화 | 기존 서비스에 기능·화면 추가 | 1 · 5 · 7 |

```
유형: enhancement
근거: 기존 {서비스명}에 {기능} 추가. GNB·수익모델은 확정 상태
```

고도화라면 **2·3·4·6·8은 이 문서에 쓰지 않는다** — 상위 문서에 이미 있다는 전제다. 없다면
고도화가 아니므로 `new` 또는 `renewal`로 다시 판정한다.

## 1. 문제 정의

어떤 문제를 푸는가. **기능을 나열하지 않고** 문제만 서술한다.
기능 없이 설명할 수 없다면 아직 범위를 정할 단계가 아니다.

> 예: 사용자가 관심 종목의 중요 이벤트를 놓친다. 확인하려면 여러 앱을 오가야 한다.

## 2. 타겟 유저

주 사용자는 누구인가. 가능하면 페르소나 1~2개로 구체화한다.

| | | |

## 3. 가치 제안 / 포지셔닝

경쟁·대안 대비 무엇이 다른가. 한 문장으로 쓴다.

> 예: {대안}은 A를 하지만 B가 없다. 우리는 B를 중심으로 A를 제공한다.

## 4. 수익모델

**무료/유료 경계가 핵심이다.** 이것이 화면의 마스킹 범위를 결정한다.

| 방식 | 구독 / 인앱결제 / 광고 / 기타 |
|---|---|
| 무료 제공 | |
| 유료 전용 | |
| 경계 기준 | 왜 그 선에서 나누는가 |

## 5. 주요 유저 플로우

핵심 시나리오 2~3개. 화면 이름이 아니라 **행동 순서**로 쓴다.
GNB·메뉴 구성은 여기서 파생되므로 이것이 6번보다 먼저다.

```
플로우 A: 진입 → 행동 → 행동 → 목적 달성
플로우 B: ...
```

## 6. GNB · 주요 메뉴 구성

5번 플로우에서 도출한다. 플로우 없이 정한 메뉴는 근거가 없다.

```
Index
├ {대메뉴 1}
│  ├ {서브메뉴}
│  └ {서브메뉴}
├ {대메뉴 2}
└ ...

GNB 밖 공통: Member(로그인·계정) · Payment(결제) · Etc(설정·전체메뉴)
```
````

## 작성 순서

**0번을 가장 먼저 쓴다.** 유형이 정해지지 않으면 어느 항목을 써야 하는지 모른다.

이후는 **1 → 2 → 3 → 4 → 5 → 6 → 7** 순서가 의존 관계에 맞다.

| 순서 | 이유 |
|---|---|
| 0 먼저 | 점검 범위를 결정. 고도화면 절반을 안 써도 된다 |
| 1·2 다음 | 나머지 전부의 전제 |
| 3·4 다음 | 화면 권한 경계의 근거 |
| 5 다음 | 6이 여기서 파생 |
| 6 다음 | 5에서 도출 |
| 7 마지막 | 메뉴가 정해진 뒤에야 우선순위를 매길 수 있다 |

8번은 언제 써도 된다. 게이트 통과에 영향을 주지 않는다.
