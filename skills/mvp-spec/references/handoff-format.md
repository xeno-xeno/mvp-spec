# 출력 계약 — spec_format: 1

이 스킬이 내는 **갱신본 문서의 형식 계약**이다. 화면 설계 단계(사람이든 도구든)는 이 계약만
전제로 읽는다. 형식을 바꾸면 하위 도구가 깨질 수 있으므로 버전을 둔다.

---

## 1. 프론트매터

```yaml
---
spec_format: 1                  # 이 계약의 버전. 필수
work_type: enhancement          # new | renewal | enhancement. 필수
tags: [ready]                   # draft | ready | done | live
screens: Feed-Latest-List-01, Feed-Article-01   # 이 문서가 정의하는 화면 ID(가ID). 필수
updated: YYYY-MM-DD
---
```

## 2. 화면 목록 표 — 문서 상단에 1개

| 화면 ID | 화면 | 레벨 | 진입 | MVP | 상태 수 |
|---|---|---|---|---|---|

| 칸 | 허용 값 |
|---|---|
| 레벨 | `Home` / `Main` / `Detail` / `기능형` |
| MVP | `1` / `2` / `3` |
| 상태 수 | 해당 화면 상태 표의 행 수 |

## 3. 화면 섹션 — 화면마다 1개, 순서 고정

```
## {화면 ID} — {화면명}
> IA: {경로} | MVP {n} | {권한 요약}

### 상태
| 상태 | 조건 | 화면 |

### 전이
| 트리거 | 목적지 | 방식 |

### 주석
1. ...
2. ...

[미결]                       ← 선택. 있으면 주석 블록 끝
· ...
```

### 칸 규칙

| 칸 | 허용 값 |
|---|---|
| 상태 행 | `기본` · `빈상태` · `무료` **필수**. 추가 상태(예: `확장`, `한도초과`) 허용 |
| 무료 행의 `화면` 칸 | `동일` / `마스킹 — {대상 요소} · {표현}` / `분기 → {화면 ID}` / `차단 → {안내 목적지}` |
| 전이 `목적지` | 화면 ID, `같은 화면 내`, `뒤로`. 목록에 없는 대상은 이름 + `※ 미정의` |
| 전이 `방식` | `화면 이동` / `모달` / `바텀시트` / `같은 화면 내` / `뒤로` |
| 주석 | 번호 목록. 한 줄 38자 권장, 넘으면 다음 줄을 5칸 들여 쓴다 |
| `[미결]` | `·` 목록. 근거 없이 대체한 값은 `상위 근거 없음`으로 표기 |

## 4. 하위 단계가 기대해도 되는 것 · 안 되는 것

| 기대해도 됨 | 기대하면 안 됨 |
|---|---|
| 위 구조와 허용 값 | 레이아웃·카피의 확정 — 문서는 정의 수준이다 |
| `분기` 목적지 ID가 화면 목록에 존재 (§3 검증 2단계) | 상태 수만큼의 화면 장수 — 상태 수는 **상한**이다. `동일`·`마스킹`은 별도 화면을 만들지 않는다 |
| `마스킹`이면 대상 요소와 표현이 적혀 있음 | 화면 ID가 최종값 — 가ID이며 화면 설계 단계에서 확정된다 |

## 5. 버전 규칙

| 변경 | 버전 |
|---|---|
| 선택 칸 추가 | 유지 |
| 칸 이름·순서·허용 값 변경, 필수 칸 추가 | `spec_format` +1 |

- 하위 도구는 **모르는 버전**을 받으면 사용자에게 알리고 진행 여부를 묻는다
- `spec_format`이 없는 문서는 **계약 이전 문서(v0)**로 본다. 무료 행 유형이 없을 수 있으므로
  하위 도구는 서술에서 판단하고 그 사실을 리포트에 적는다
