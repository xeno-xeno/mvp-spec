# 질의 보완 모드

§0-2에서 쓰는 절차다. 필수 3개(2·3·4)가 모두 없으면 이 모드가 **기본**이고, 그 외에는 사용자가
"질문으로 함께 채우기"를 고른 경우에만 쓴다.

## 성격

- 게이트 항목을 **러프한 수준**까지 채운다. 완성형 PRD를 대신 쓰지 않는다
- 답을 **임의로 만들지 않는다**. 후보를 제안할 수는 있지만 확정은 사용자가 한다
- 결과물은 `mvp-template.md` 구조로 채운 Master 초안이다. 사용자가 이후 직접 다듬을 수 있다

## 진행

```
① 점검 항목 중 문서에 없는 것만, 아래 순서로 묻는다 (한 번에 최대 2개)
② 답을 템플릿 구조에 기록한다 — 중간 보고 없음
③ 끝: Master 초안 파일 + 게이트 2줄 → 통과하면 "2단계로 이어갈까요? (기본: 예)"
```

§0-1 점검에서 이미 충족된 항목은 묻지 않는다. 질문 수는 비어 있는 항목 수만큼만 생기며, `(n/N)`의 N은
**이번에 실제로 묻는 질문 수**(메뉴 제안 포함)다. 아래 표의 `/6`은 전부 없을 때의 최대치다.

- 1번은 비어 있을 때만 묻는다. 서비스·이용자를 각각 묻는다
- 2번은 **저니가 없을 때만** 묻는다. 저니가 없으면 포지셔닝도 비어 있을 때 함께 묻고, 이미 있으면 건너뛴다. 저니가 있으면 포지셔닝이 없어도 묻지 않는다

## 질문 순서와 예 (최대 6개, 3회 왕복)

| 회차 | 항목 | 질문 예 |
|---|---|---|
| 1 | 1 핵심 서비스 | `(1/6) 어떤 서비스를 제공하나요? 한 문장으로 (예: 동네 운동 모임을 찾아 주는 앱)` |
| 1 | 1 주 이용자 | `(2/6) 주 이용자는? (예: 퇴근 후 운동하는 30대 직장인)` |
| 2 | 2 포지셔닝 | `(3/6) 다른 방법 대비 다른 점 한 가지? (예: 근처 모임을 1분 안에 찾는다)` |
| 2 | 2 유저 저니 | `(4/6) 핵심 시나리오 2~3개를 순서로? (예: 검색 → 모임 상세 → 참여 신청 → 알림)` |
| 3 | 3 메뉴 구성 | 묻지 않고 제안 — `(5/6) 저니 기준 메뉴안: 홈 / 탐색 / 내 모임 / 마이. 이대로? (기본: 예)` |
| 3 | 4 기능 우선순위 | `(6/6) 1순위로 만들 기능 2~3개? (후보: …)` — 후보는 앞의 답에서 뽑는다 |

## 모를 때

| 사용자 답 | 처리 |
|---|---|
| "모르겠다", "나중에" | `[미결]`로 기록하고 다음 질문으로 |
| "기본으로"·"그대로" (기본값 없는 열린 질문에) | 예시를 답으로 쓰지 않는다. 한 번만 다시 묻고, 그래도 없으면 `[미결]` |
| "추천해 줘" | 앞의 답을 근거로 후보 2~3개를 제안하고 고르게 한다. 고르지 않으면 `[미결]` |

진행 차단 항목(2·3·4)이 `[미결]`로 남으면 마지막 게이트 2줄이 `→ 진행 불가`로 나온다. 그대로
초안을 넘기고 멈춘다 — 억지로 채우지 않는다.

저니가 `[미결]`이면 메뉴 제안도 `[미결]`로 두고 이어간다. `(n/N)`의 N은 바꾸지 않는다.

## 기록 규칙

- 프론트매터에 `tags: [draft]`를 넣는다
- 사용자의 표현을 최대한 그대로 쓴다. 다듬더라도 의미를 바꾸지 않는다
