# 질의 보완 모드

§0-3에서 사용자가 "질문으로 함께 채우기"를 고른 경우의 절차다. **기본은 템플릿이고, 이 모드는
선택이다.**

## 성격

- 게이트 항목을 **러프한 수준**까지 채운다. 완성형 PRD를 대신 쓰지 않는다
- 답을 **임의로 만들지 않는다**. 후보를 제안할 수는 있지만 확정은 사용자가 한다
- 결과물은 `mvp-template.md` 구조로 채운 Master 초안이다. 사용자가 이후 직접 다듬을 수 있다

## 진행

```
① 유형 확인 — 프론트매터·서술로 이미 정해졌으면 생략
② 유형별 필수 항목 중 문서에 없는 것만, 아래 순서로 묻는다 (한 번에 최대 2개)
③ 답을 템플릿 구조에 기록한다 — 중간 보고 없음
④ 끝: Master 초안 파일 + 게이트 3줄 → 통과하면 "2단계로 이어갈까요? (기본: 예)"
```

§0-2 점검에서 이미 충족된 항목은 묻지 않는다. 질문 수는 비어 있는 항목 수만큼만 생긴다.

## 질문 순서와 예 — 신규 · 리뉴얼 (최대 7개, 4회 왕복)

| 회차 | 항목 | 질문 예 |
|---|---|---|
| 1 | 1 문제 정의 | `(1/7) 이 서비스가 푸는 문제를 한 문장으로? (예: 동네 운동 모임을 찾기 어렵다)` |
| 1 | 2 타겟 유저 | `(2/7) 주 사용자는? (예: 퇴근 후 운동하는 30대 직장인)` |
| 2 | 3 가치 제안 | `(3/7) 다른 방법 대비 다른 점 한 가지? (예: 근처 모임을 1분 안에 찾는다)` |
| 2 | 4 수익모델 | `(4/7) 수익 방식과 무료·유료 경계? (구독 / 인앱결제 / 광고 / 미정)` |
| 3 | 5 유저 플로우 | `(5/7) 핵심 시나리오 2~3개를 순서로? (예: 검색 → 모임 상세 → 참여 신청 → 알림)` |
| 4 | 6 GNB | 묻지 않고 제안 — `(6/7) 플로우 기준 메뉴안: 홈 / 탐색 / 내 모임 / 마이. 이대로? (기본: 예)` |
| 4 | 7 우선순위 | `(7/7) 1순위로 만들 기능 2~3개? (후보: …)` — 후보는 앞의 답에서 뽑는다 |

## 질문 순서와 예 — 고도화 (최대 3개, 2회 왕복)

| 회차 | 항목 | 질문 예 |
|---|---|---|
| 1 | 1 문제 정의 | `(1/3) 이번에 추가하는 기능이 푸는 문제는?` |
| 1 | 5 유저 플로우 | `(2/3) 기존 서비스의 어디에서 들어와 어디로 나가나요?` |
| 2 | 7 우선순위 | `(3/3) 이번 범위의 1순위 기능은? (후보: …)` |

고도화의 2·3·4·6은 상위 문서에 있다는 전제다. 상위 문서에도 없다면 고도화가 아니므로 §0-1로
돌아가 유형을 다시 정한다.

## 모를 때

| 사용자 답 | 처리 |
|---|---|
| "모르겠다", "나중에" | `[미결]`로 기록하고 다음 질문으로 |
| "추천해 줘" | 앞의 답을 근거로 후보 2~3개를 제안하고 고르게 한다. 고르지 않으면 `[미결]` |

진행 차단 항목(4·5·6·7)이 `[미결]`로 남으면 마지막 게이트 3줄이 `→ 진행 불가`로 나온다. 그대로
초안을 넘기고 멈춘다 — 억지로 채우지 않는다.

## 기록 규칙

- 프론트매터에 `work_type`과 `tags: [draft]`를 넣는다. 다음 호출 때 유형을 다시 묻지 않게 된다
- 사용자의 표현을 최대한 그대로 쓴다. 다듬더라도 의미를 바꾸지 않는다
- 질문하지 않은 항목(8 성공 지표 등)은 템플릿의 빈칸으로 남긴다
