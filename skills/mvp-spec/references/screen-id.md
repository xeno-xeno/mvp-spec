# 화면 ID 명명 규칙

화면 ID를 부여할 때 읽는다. 레벨 판정 → 소속 확인 → 이름 작성 순서로 진행한다.

## 레벨 — 소속 이전에 먼저 정한다

서비스 화면은 사이트맵상 네 레벨로 나뉜다. 레벨에 따라 ID 패턴이 달라진다.

| 레벨 | 정의 | ID 패턴 |
|---|---|---|
| **Home** | 서비스 최초 진입 화면 | `Home-{순번}` |
| **Main** | Home 하위 화면 중 콘텐츠 단건이 아닌 것 — 서브메인(Index 바로 아래 대메뉴) 랜딩, 서브탭 전환, 리스트, 대시보드 | `{대메뉴}-{소메뉴}-{화면명}-{순번}` |
| **Detail** | 콘텐츠 단건의 본문/상세 — 기사 본문, 항목 상세, 개별 데이터 상세 | `{대메뉴}-{화면명}-{순번}` (소메뉴 생략) |
| **기능형** | 특정 대메뉴에 고정되지 않고 여러 진입점에서 열리는 부속 기능 — 모달, 필터, 결제, 로그인, 설정 | `{화면명}-{순번}` (대메뉴 없음) |

**Detail 판정**은 형태(리스트냐 카드냐)가 아니라 **콘텐츠 단건을 보여주는가**로 한다. 리스트에
카드가 여러 장 있어도 그 자체는 Main이고, 카드를 탭해 들어간 단건 화면이 Detail이다.

**기능형 판정**은 **"이 화면이 한 대메뉴에서만 열리는가"**로 한다. 여러 대메뉴의 카드에서 공통으로
열리면 대메뉴 접두를 붙이지 않는다.

```
Home-01
Feed-Latest-List-01               ← Main: Latest 서브탭 리스트
Feed-Article-01                   ← Detail: 콘텐츠 본문 (소메뉴 생략)
Explore-ItemDetail-01             ← Detail: 항목 단건 상세
ShareSheet-01                     ← 기능형: 여러 대메뉴에서 진입
```

## GNB 밖 대메뉴 — 공통 영역

GNB 탭 외에도 대메뉴로 취급해야 하는 영역이 있다. IA에서 계층 밖에 라벨로만 남아 화면 수가
0으로 보이는 경우가 많으니, Depth 1에 명시적으로 편입한다.

| 대메뉴 | 포함 |
|---|---|
| `Member` | 로그인 · 가입 · 계정정보 · 구독상태 |
| `Payment` | 결제 상품 · 구독 시트 · 복구/환불 |
| `Etc` | 전체 메뉴 · 설정 |

알림 뱃지처럼 헤더에서 진입하는 화면은 별도 카테고리를 만들지 않는다. 대개 특정 대메뉴(예:
특정 탭의 알림 목록)나 `Etc`의 하위 화면이므로, 그 소속을 먼저 확인한다.

## 한 화면 = 한 ID

상태가 여러 개여도 화면 ID는 하나다. 상태(기본·빈상태·무료 등)는 상태 표의 행으로 구분하고 ID를
나누지 않는다. **ID를 따로 주는 경우는 두 가지뿐이다.**

| 경우 | 처리 |
|---|---|
| 무료 행 유형이 `분기` — 무료면 다른 화면으로 전환 | 전환되는 화면에 별도 ID |
| 같은 기능의 변형을 하나로 정의 (예: 콘텐츠 타입별 모달) | 기능형 ID 하나로 묶고 변형은 상태 표에 |

## 표기 규칙

- 대메뉴·소메뉴는 IA의 탭 표기를 그대로 쓴다 (`Feed`, `Latest`, `Explore`)
- 화면명은 PascalCase, 축약하지 않는다 (`List`, `ItemDetail`, `Article`)
- **화면 성격이 드러나는 단어를 쓴다.** `Body`처럼 범용적인 말은 피한다 — 콘텐츠 본문(기사)이면
  `Article`, 목록이면 `List`, 상세면 `Detail`. 구조적 컨테이너 이름(레이아웃 프레임의
  `header`/`body`/`footer`)과 화면 ID는 다른 층위이므로 헷갈리지 않는다
- 같은 소메뉴 안에서 화면이 여러 개면 화면명으로 구분하고, 정말 동일한 화면의 반복만 순번으로
  늘린다
- 폐기된 번호는 재사용하지 않는다. 재부여하면 화면 설계 문서의 주석과 끊긴다
