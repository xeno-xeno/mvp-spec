# mvp-spec

`v1.0.0` · 출력 계약 `spec_format: 1` · [사용 가이드](GUIDE.md) · [변경 이력](CHANGELOG.md)

> An Agent Skill (Korean) that checks whether an MVP / planning document is ready for screen design,
> confirms the screen list and state count, and finds logical gaps such as missing screens, broken
> flows, and permission conflicts. If the document is missing or thin, it hands you a template — or
> fills the required items together with you through short questions.

<br>

바이브코딩으로 누구나 개발을 할 수 있는 시대입니다.
AI에게 프롬프트로 요청하면 딸깍 만들어진다고들 합니다. 하지만 토큰을 아끼면서 원하는 결과물을 얻으려면
서비스 기능 정의 문서(PRD 수준까지는 아니더라도)가 필요합니다. 개발 프로젝트에서 PRD, IA, MVP 정의는 익숙한
작업이지만, 비기획자에게는 이 문서를 정리하는 것 자체가 도전입니다.

`mvp-spec`은 MVP·기획 문서가 **화면 설계로 넘어갈 수 있는지 확인**하고, 화면 목록과 장수를 정하는 Agent Skill입니다.
문서가 없거나 비어 있어도 괜찮습니다. 작성 템플릿을 받거나, 질문에 답하면서 필수 항목을 함께 채울 수 있습니다.

이 Skill은 AI Agent 와의 협업에 효과를 발휘합니다.
MVP 문서를 화면 설계 수준으로 정리하면 다음을 기대할 수 있습니다.

> 1. 요건(문제 정의 등) 항목의 누락 확인
> 2. 유저 저니 · 메뉴 구조 · 화면 이동의 구조화
> 3. 화면 목록·장수 확정, 빠진 동선·무료/유료 기준 충돌 같은 논리 점검 (내용의 좋고 나쁨은 평가하지 않습니다)


이 스킬은 총 2단계로 구성됩니다.

1. **1단계 — 요건 게이트(필수 항목 점검).** 아이디어 메모 수준의 문서를 MVP 단위로 정리합니다. 필수 항목 8개가
  있는지 보고, 빠진 항목은 질문에 답하며 함께 채울 수 있습니다. 답은 사용자가 정합니다.
2. **2단계 — 문서 정리.** 정리된 문서를 화면별로 나누고 상태·전이(화면 이동)·주석을 붙입니다. 화면이 몇 장인지도
  이때 정합니다. 이 형식은 와이어프레임을 자동 생성하는 도구(예: Figma 연동)가 읽을 수 있게 맞춰져 있습니다.

## 이런 분께


| 대상                                 | 이렇게 씁니다                             |
| ---------------------------------- | ----------------------------------- |
| 기획서는 있는데 **화면이 몇 장인지** 불분명한 기획자·PM | 문서를 첨부하고 "화면 설계로 넘어갈 수 있는지 봐줘"      |
| 아이디어 메모만 있는 **비기획자**               | 메모를 주고 질문에 답하며 필수 항목을 채움 (질의 보완 모드) |
| 기획 문서를 받아 화면 설계를 시작하는 디자이너·개발자     | 시작 전에 빠진 화면과 끊긴 동선을 확인              |




## 하는 일 · 하지 않는 일


| 한다                                  | 하지 않는다                                 |
| ----------------------------------- | -------------------------------------- |
| 화면 설계에 필요한 내용이 문서에 있는지 점검 (요건 게이트)  | 완성형 PRD를 대신 작성                         |
| 화면 목록 · 화면 ID · 상태 · 전이를 정리하고 장수 계산 | 와이어프레임·디자인 생성 (그런 도구에 넘길 문서를 준비하는 데까지) |
| 빠진 화면, 끊긴 동선, 문서끼리 어긋난 무료/유료 기준 찾기  | 문서 요약, 카피라이팅                           |


PRD를 써 주는 스킬은 이미 많습니다. `mvp-spec`은 그 **다음 단계**입니다. 쓴 문서로 화면 설계를 시작해도 되는지
확인합니다. 질문으로 채우는 질의 보완 모드도 화면을 그릴 수 있을 만큼만 채웁니다. PRD를 대신 써 주지는 않습니다.

사용법·단계별 규칙·출력 형식·FAQ는 **[사용 가이드](GUIDE.md)**에 있습니다.

## 활용 방법

1. [설치](#설치)합니다.
2. 기획 문서를 첨부합니다. **문서가 없어도 됩니다.**
3. 이렇게 요청합니다.

```
- 첨부한 Master.md와 Feed.md가 화면 설계로 넘어갈 수 있는지 검토해줘.
- 이 기획서로 화면이 몇 장 나오는지 정리해줘.
- 기획서는 없고 아이디어만 있어요. 화면 설계까지 정리하고 싶어요.
```

## 필수 점검 항목 8개

1단계에서 문서에 아래 항목이 **있는지** 확인합니다(잘 썼는지는 보지 않습니다).

1. 문제 정의
2. 타겟 유저
3. 가치 제안 · 포지셔닝
4. 수익모델
5. 유저 저니
6. GNB · 메뉴 구성
7. 기능 우선순위
8. 성공 지표

고도화(기존 서비스에 기능 추가)는 1 · 5 · 7번만 봅니다. 항목별 이유와 작업 유형별 규칙은 [사용 가이드](GUIDE.md#1단계--요건-게이트)에 있습니다.

## 설치

**Claude 앱 (claude.ai)**

1. [Releases](https://github.com/xeno-xeno/mvp-spec/releases/latest)에서 `mvp-spec-1.0.0.skill`을 내려받습니다.
2. 설정의 **Customize > Skills**에서 `+` → **Create skill** → **Upload a skill**로 파일을 올립니다.
  (메뉴 이름은 앱 버전에 따라 다를 수 있습니다.)
3. 스킬이 켜져 있는지, **Settings > Capabilities**에서 코드 실행이 켜져 있는지 확인합니다.

`.skill` 파일이 올라가지 않으면 확장자를 `.zip`으로 바꿔 올려 보세요. 같은 압축 파일입니다.

**Claude Code**

```
npx skills add xeno-xeno/mvp-spec --skill mvp-spec
```

직접 복사하려면 이 레포를 받아 `skills/mvp-spec/` 폴더를 `~/.claude/skills/mvp-spec/`(개인) 또는
프로젝트의 `.claude/skills/mvp-spec/`에 복사합니다.

**업데이트** — Claude 앱은 기존 스킬을 지운 뒤 새 파일을 추가합니다. `npx skills`로 설치했다면
`npx skills update`를 실행합니다. 설치된 버전은 `SKILL.md` 프론트매터의 `metadata.version`에서 확인합니다.

## 알려진 한계


| 구분    | 내용                                                          |
| ----- | ----------------------------------------------------------- |
| 내용 생성 | 기획 내용을 대신 만들어 주지 않습니다. 질의 보완 모드도 화면 설계를 시작할 수 있는 수준까지만 채웁니다 |
| 빠진 화면 | 이름이 어긋난 곳, 연결이 끊긴 화면은 찾아냅니다. "있어야 하는데 아예 없는 화면"은 사람이 판단합니다  |
| 검증 범위 | 규칙은 한 서비스(모바일 앱)의 문서로 검증됐습니다. 다른 도메인에서는 예외가 나올 수 있습니다       |




## 구성

```
skills/mvp-spec/
├ SKILL.md                         진행 절차
└ references/
  ├ handoff-format.md              출력 계약 (spec_format: 1)
  ├ mvp-template.md                요건이 부족할 때 제공하는 작성 템플릿
  ├ fill-mode.md                   질의 보완 모드 — 질문으로 템플릿 채우기
  ├ gate-rationale.md              유형 판정·항목 선택 근거, 자주 걸리는 패턴
  ├ screen-id.md                   화면 ID 명명 규칙
  ├ reporting.md                   리포트 기본·상세 형식
  └ doc-format.md                  화면 섹션 작성 예시
```



## 버전 관리

[유의적 버전](https://semver.org/lang/ko/)(MAJOR.MINOR.PATCH)을 따릅니다. 출력 계약(`spec_format`)이 바뀌면
MAJOR를 올리므로, 이 스킬의 산출물을 읽는 도구는 MAJOR 버전만 확인하면 호환 여부를 알 수 있습니다.
변경 이력은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.

## 출처

- 실행 원칙(가정하지 말 것, 최소한만 만들 것, 건드린 것만 고칠 것, 검증 루프)은 Andrej Karpathy가 정리한
LLM 에이전트 지침에서 가져와 문서 검토 맥락으로 옮겼습니다. 해당 스킬을 함께 설치할 필요는 없습니다.
- 게이트 항목은 공개된 MVP 체크리스트와 PRD 템플릿이 공통으로 요구하는 요소에 GNB·메뉴 구성을 더한 것입니다.
