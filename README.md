# mvp-spec

`v2.0.0` · 출력 계약 `spec_format: 2` · [사용 가이드](GUIDE.md) · [변경 이력](CHANGELOG.md)

> An Agent Skill (Korean) that checks whether an MVP / planning document is ready for screen design,
> confirms the screen list and state count, and finds logical gaps such as missing screens and broken
> flows. If the document is missing or thin, it hands you a template — or
> fills the required items together with you through short questions.

<br>

바이브코딩으로 누구나 개발을 할 수 있는 시대입니다.
AI에게 프롬프트로 요청하면 딸깍 만들어진다고들 합니다. 하지만 토큰을 아끼면서 원하는 결과물을 얻으려면
서비스 기능 정의 문서(PRD 수준까지는 아니더라도)가 필요합니다. 개발 프로젝트에서 PRD, IA, MVP 정의는 익숙한
작업이지만, 비기획자에게는 이 문서를 정리하는 것 자체가 도전입니다.

`mvp-spec`은 MVP·기획 문서가 **화면 설계로 넘어갈 수 있는지 확인**하고, 화면 목록과 장수를 정하는 Agent Skill입니다.
문서가 없거나 비어 있어도 괜찮습니다. 질문에 답하면서 필수 항목을 함께 채우거나, 작성 템플릿을 받을 수 있습니다.

> **초기 서비스 기획을 최소한으로, 빠르게.** 이 스킬은 간결하고 빠르게 MVP를 쓰는 데 맞춰져 있습니다. 점검 항목은 4개뿐이고, 수익모델·성공 지표는 묻지 않습니다. 새 서비스를 처음 기획할 때를 위한 것이라 기존 서비스에 기능을 더하는 경우는 따로 나누지 않았습니다. 메뉴 구성은 "기존 메뉴 그대로" 한 줄이면 충족입니다.

AI Agent와 함께 쓸 때 효과가 큽니다. MVP 문서를 화면 설계 수준으로 정리하면 이런 점이 좋아집니다.

- 빠진 항목이 없는지 먼저 확인할 수 있습니다.
- 사용자가 하는 행동 순서, 메뉴, 화면 간 이동이 정리됩니다.
- 화면이 몇 장인지 정해지고, 빠진 화면이나 끊긴 동선을 찾을 수 있습니다. (내용이 좋은지 나쁜지는 평가하지 않습니다)

이 스킬은 두 단계로 진행됩니다.

1. **1단계 — 필수 항목 점검.** 아이디어 메모 수준의 문서에 꼭 필요한 4가지가 있는지 봅니다. 빠진 게 있으면 질문에 답하면서 같이 채우고, 답은 항상 사용자가 정합니다.
2. **2단계 — 문서 정리.** 문서를 화면별로 나누고, 화면마다 상태와 이동 경로, 메모를 붙입니다. 화면이 몇 장인지도 이때 정합니다. 정리된 형식은 와이어프레임 자동 생성 도구(예: Figma 연동)가 읽을 수 있게 맞춰져 있습니다.

## 이런 분께

- **아이디어만 있는 1인 개발자·비개발자** — 메모나 한두 줄만 줘도 됩니다. 질문에 답하다 보면 필수 항목이 채워집니다.
- **바이브코딩을 시작하려는 분** — AI에게 "앱 만들어줘" 하기 전에, 화면이 몇 장이고 어떻게 이어지는지부터 정리합니다.
- **기획서는 있는데 화면이 몇 장인지 모르겠는 분** — 문서를 올리고 "화면 설계로 넘어가도 되는지 봐줘"라고 하면 됩니다.

## 하는 일 · 하지 않는 일

**해 주는 것**

- 화면을 그리기 전에 필요한 내용이 문서에 있는지 확인합니다.
- 화면 목록, 화면 ID, 상태, 화면 간 이동을 정리하고 장수를 셉니다.
- 빠진 화면, 끊긴 동선, 정의가 비어 있는 핵심 기능을 찾아냅니다.

**해 주지 않는 것**

- 기획서(PRD)를 대신 써 주지 않습니다.
- 와이어프레임이나 디자인을 만들지 않습니다. 그런 도구에 넘길 문서를 준비하는 데까지입니다.
- 문서 요약이나 카피라이팅은 하지 않습니다.

PRD를 써 주는 스킬은 이미 많습니다. `mvp-spec`은 그 **다음 단계**로, 쓴 문서로 화면 설계를 시작해도 되는지 확인합니다. 질문으로 채우는 방식도 화면을 그릴 수 있을 만큼만 채웁니다.

사용법·단계별 규칙·출력 형식·FAQ는 **[사용 가이드](GUIDE.md)**에 있습니다.

## 활용 방법

1. [설치](#설치)합니다.
2. 기획 문서를 첨부합니다. **문서가 없어도 됩니다.**
3. 이렇게 요청합니다.

```
- 첨부한 Master.md와 Feed.md가 화면 설계로 넘어갈 수 있는지 검토해줘.
- 이 기획서로 화면이 몇 장 나오는지 정리해줘.
- 기획서는 없고 아이디어만 있어요. 화면 설계까지 정리하고 싶어요.
```

## 점검 항목 4개

1단계에서 문서에 아래 항목이 **있는지** 확인합니다(잘 썼는지는 보지 않습니다).

1. **제공할 핵심 서비스와 주 이용자** — 무엇을 누구에게 주는지
2. **포지셔닝과 유저 저니** — 다른 서비스와 다른 점, 사용자가 하는 행동 순서
3. **메뉴 구성** — 화면 아래·위에 늘 보이는 메뉴
4. **기능 우선순위** — 이번에 만들 것과 나중에 할 것

기존 서비스에 기능을 더하는 문서라면 3번은 "기존 메뉴 그대로"라고 한 줄이면 충족입니다. 항목별 이유는 [사용 가이드](GUIDE.md#1단계--필수-항목-점검)에 있습니다.

## 설치

**Claude 앱 (claude.ai)**

1. [Releases](https://github.com/xeno-xeno/mvp-spec/releases/latest)에서 `mvp-spec-2.0.0.skill`을 내려받습니다.
2. 설정의 **Customize > Skills**에서 `+` → **Create skill** → **Upload a skill**로 파일을 올립니다.
  (메뉴 이름은 앱 버전에 따라 다를 수 있습니다.)
3. 스킬이 켜져 있는지, **Settings > Capabilities**에서 코드 실행이 켜져 있는지 확인합니다.

`.skill` 파일이 올라가지 않으면 확장자를 `.zip`으로 바꿔 올려 보세요. 같은 압축 파일입니다.

**Claude Code**

```
npx skills add xeno-xeno/mvp-spec --skill mvp-spec
```

직접 복사하려면 이 레포를 받아 `skills/mvp-spec/` 폴더를 `~/.claude/skills/mvp-spec/`(개인) 또는
프로젝트의 `.claude/skills/mvp-spec/`에 복사합니다.

**업데이트** — Claude 앱은 기존 스킬을 지운 뒤 새 파일을 추가합니다. `npx skills`로 설치했다면
`npx skills update`를 실행합니다. 설치된 버전은 `SKILL.md` 프론트매터의 `metadata.version`에서 확인합니다.

## 알려진 한계

- **내용은 대신 만들어 주지 않습니다.** 질문으로 채우는 방식도 화면 설계를 시작할 수 있는 수준까지만 채웁니다.
- **"아예 없는 화면"은 못 찾습니다.** 이름이 어긋났거나 연결이 끊긴 화면은 찾아내지만, 있어야 하는데 없는 화면은 사람이 판단합니다.
- **한 서비스(모바일 앱) 문서로만 검증했습니다.** 다른 분야에서는 예외가 나올 수 있습니다.

## 구성

```
skills/mvp-spec/
├ SKILL.md                         진행 절차
└ references/
  ├ handoff-format.md              출력 계약 (spec_format: 2)
  ├ mvp-template.md                요건이 부족할 때 제공하는 작성 템플릿
  ├ fill-mode.md                   질의 보완 모드 — 질문으로 템플릿 채우기
  ├ gate-rationale.md              항목 선택 근거, 자주 걸리는 패턴
  ├ screen-id.md                   화면 ID 명명 규칙
  ├ reporting.md                   리포트 기본·상세 형식
  └ doc-format.md                  화면 섹션 작성 예시
```



## 버전 관리

[유의적 버전](https://semver.org/lang/ko/)(MAJOR.MINOR.PATCH)을 따릅니다. 출력 계약(`spec_format`)이 바뀌면
MAJOR를 올리므로, 이 스킬의 산출물을 읽는 도구는 MAJOR 버전만 확인하면 호환 여부를 알 수 있습니다.
변경 이력은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.

## 출처

- 실행 원칙(가정하지 말 것, 최소한만 만들 것, 건드린 것만 고칠 것, 검증 루프)은 Andrej Karpathy가 정리한
LLM 에이전트 지침에서 가져와 문서 검토 맥락으로 옮겼습니다. 해당 스킬을 함께 설치할 필요는 없습니다.
- 게이트 항목은 공개된 MVP 체크리스트와 PRD 템플릿이 공통으로 요구하는 요소를 일반 사용자 눈높이로 3개로 묶고 메뉴 구성을 더해 4개로 만든 것입니다. 수익모델·성공 지표는 화면 설계에 필요하지 않아 뺐습니다.
